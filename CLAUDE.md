# На сколько большая

Страница из независимых интерактивных визуализаций о масштабе Вышки. Каждая
визуализация отвечает на свой вопрос («на сколько Вышка заполнит „Лужники“»,
«сколько это в вагонах метро» и т.д.), но все они про одни и те же ~75 тысяч
человек и выглядят как части одного целого.

Ванильный HTML + CSS + ES-модули. Сборки нет, зависимостей нет, фреймворков нет.

## Как запустить

ES-модули не работают по `file://`, нужен локальный сервер:

```bash
python3 tools/serve.py
```

Дальше `http://localhost:8000`.

Это тот же `http.server`, только с запретом кэширования. Обычный
`python3 -m http.server` заголовков о кэше не шлет, браузер решает сам — и
держит у себя старые скрипты и стили. Правка при этом уже на диске, а на
экране прежняя страница, и выглядит это так, будто ничего не изменилось.
Если браузер успел закэшировать файлы до перехода на этот сервер, его нужно
один раз обновить принудительно (Cmd+Shift+R), дальше заголовки работают сами.

## Структура

```
index.html          каркас: подключает стили и монтирует список модулей
styles/tokens.css   палитра, тени, радиусы — единственный источник цвета
styles/layout.css   секции, колонки и общие компоненты (карточки, тумблеры, кнопки)
data/hse.js         численность Вышки по городам + цвета городов
lib/format.js       nf / pct / plural
lib/ui.js           mountCanvas()
lib/color.js        tint()
lib/page.js         прогресс чтения, ленивый старт секций, липкие сцены
viz/<name>.js       одна визуализация — один модуль
assets/             картинки
tools/              сборка автономной копии, проверка текстов, числа на экране
teaser/             рисованный тизер на 30 секунд (canvas + звук WebAudio)
```

**Числа на экране для настоящего телефона.** Консоли там нет, а вся арифметика
чтения — положение секции, доли открытия, высоты — живет в числах. Адрес с
`?debug` грузит `tools/debug-hud.js`: полоска внизу экрана, в ней прокрутка,
высота окна, номер и положение секции, `--intro-k`, `--intro-body`,
`--lead-away`, `--lead-hold`, доли частей и их прямоугольники. Без `?debug`
файл не грузится вовсе, к странице отношения не имеет и ничего в ней не
трогает.

Тизер открывается через `python3 tools/teaser-server.py` по адресу
`http://localhost:8001/teaser/`. Кнопка «Собрать видео» рисует ролик по
кадрам, кодирует его средствами браузера (WebCodecs) и кладет
`teaser/teaser.mp4` в проект. Данные и цвета тизер берет из `data/hse.js` и
`tokens.css`, но ни одной цифры не называет — ни числа стран, ни вместимости
арены, ни годов на ленте времени. Тизер только задает вопросы, ответы
читатель находит на странице.

## Автономная копия

`На сколько большая.html` — вся страница одним файлом: стили, скрипты, шрифты и
картинки внутри, внешних запросов нет. Её можно открыть двойным кликом или
переслать. Файл собирается из исходников, руками его не правят:

```bash
python3 tools/build-standalone.py
```

Состав разделов сборщик берёт из `MODULES` в `index.html`, а библиотеки и
данные — из импортов, так что и новый блок, и новый файл в `lib/` или `data/`
попадают в выгрузку сами. Если модуль собирает путь к картинке из имени
(`assets/flags/${code}.svg`), путь целиком в коде не встречается — для такой
папки в сборщике добавляется строка в `BY_NAME`, и он строит таблицу файлов.

Выгрузку стоит пересобирать после заметных правок — иначе она тихо отстаёт от
страницы.

Второй копией собирается телефонный вид — он читается прокруткой в одну
колонку на любом экране:

```bash
python3 tools/build-standalone.py --mobile
```

Получается `На сколько большая — телефон.html`. На самом телефоне обычная
копия ведёт себя точно так же (режим выбирается по ширине), эта нужна, чтобы
посмотреть телефонный вид на большом экране или на планшете: в ней из стилей
оставлена ветка «до 860px», а вопросы о ширине через `matchMedia` отвечаются
так, как ответил бы телефон.

Ветка раскрывается не только в `styles/`, но и в стилях, которые модуль везет
внутри себя (и библиотека — тоже: карта города в `lib/town-map.js`). Иначе
телефонная копия на большом экране отвечала телефоном только за общую
раскладку: колонки не складывались в одну, а поезд во всю ширину у метро
оставался виден и распирал колонку до своих 4956 пикселей.

## Контракт модуля

Каждый файл в `viz/` экспортирует ровно две вещи:

```js
export const meta = {
  id: 'stadium',            // якорь секции, латиницей
  title: 'Заголовок',       // каркас сам рисует шапку секции
  subtitle: 'Подзаголовок',
  short: 'Стадион'          // короткое имя раздела, два-три слова
};

export function init(root) {
  // root — это пустой <div class="viz-body">, растянутый на высоту секции.
  // Модуль сам создаёт внутри свою разметку и вешает обработчики.
}
```

**Короткое имя раздела (`short`).** Заголовки у блоков длинные — у финала
шестьдесят символов. Там, где нужно назвать раздел в одну строчку, берется
`short`. На телефоне это список разделов, который открывается касанием полоски
сверху: восемь строк по два слова читаются, а восемь заголовков по шестьдесят
символов — нет. Пишется без кавычек и без цифр, двумя-тремя словами, и не
выдает поворота блока: у финала это «Все цифры», а не «Это ты».

Полоски с именем раздела в углу экрана на телефоне больше нет: она приходила
с каждым движением пальца и вставала поверх картинки — а в верхнем углу у
блока самое важное, счет на трибунах или первая строка истории.

**`init` вызывается не сразу**, а когда читатель подходит к секции — точнее,
**на один блок раньше**: каркас собирает следующий раздел в паузе, пока
читатель смотрит текущий (`prepare()` в широкой машине и `warm()` в
телефонной, обе в `lib/stepper.js`, через `requestIdleCallback`). Сборка блока
стоит от 8 до 70мс, и такт, который приводит раздел на экран, — худший момент,
чтобы их потратить: страница едет.

На телефоне подготовки сначала не было: блок собирал наблюдатель за въездом
секции, а тот срабатывает за 400 пикселей до нее — такт же увозит страницу на
полтора экрана, то есть сборка приходилась ровно на тот такт, который блок и
привозит. У легких блоков это восемь миллисекунд и незаметно, а флаги с их
128 картинками и стена профессий в полтысячи узлов рвали анимацию прихода:
блок «долго не появлялся», а потом дергался. Наблюдатель остался — он
открывает блок (`open()`) и достраивает то, до чего подготовка не дошла.

Отсюда два следствия для модуля. Рассчитывать на то, что он стартовал при
загрузке, по-прежнему нельзя. И анимацию, которую читатель должен увидеть,
не запускают прямо в `init` — она отыграет за кадром; такую анимацию ведут
через `step()`, который каркас зовёт в нужный момент.

**Титульный экран.** Страница открывается шапкой на весь экран, дальше первый
блок сначала показывает свои заголовок и подзаголовок по центру экрана
(крупнее обычного, но мельче главного заголовка), а затем они уезжают на место
и проявляется сама визуализация. Это делает `mountIntro()` в `lib/page.js`,
каркас включает её для первого модуля в `MODULES`. Модулю делать ничего не
нужно. Любой другой модуль может открываться так же — достаточно объявить в
`meta` поле `intro: true`.

**Раздел без титульной карточки (`card: false`).** Открытие есть, карточки нет:
заголовок не выходит крупно на середину экрана, чтобы потом уехать наверх и
уменьшиться, — он стоит на своем месте, в своем кегле, и проявляется вместе с
блоком. Один такт на обоих: заголовок и блок начинают и кончают появление
одновременно, поднявшись на шестнадцать пикселей. Так открываются «Стадион» и
«Годы учебы» — разделы, у которых переходный экран перед заголовком уже все
сказал словами, и отдельный кадр с одним заголовком был тактом без картинки.

```js
export const meta = { id, title, subtitle, lead, intro: true, card: false };
```

Переходный экран при этом остается как был: он набран от `--intro-k`, который
каркас продолжает считать, — меняется только то, что делает заголовок. Каркас
ставит на секцию класс `intro-plain`; что именно по нему не играет, написано в
`layout.css` рядом с самой карточкой.

Два следствия. Подзаголовок на телефоне не складывается — прочитать его больше
негде, и место он занимает насовсем. А последняя остановка открытия на телефоне
— конец открытия, а не верх `.viz-body`: заголовок там стоит у верхнего края, а
блок начинается прямо под ним. Довезти страницу до верха блока значило бы увезти
заголовок за край тем же махом, которым он появился.

**Вспышка на стыке (необязательно).** У другого конца истории свой занавес.
Блок, который заканчивается тем, что делается снимок, объявляет в `meta`
поле `flash: true` — и следующий раздел приходит через вспышку камеры: экран
быстро белеет, за белым страница переходит к следующему блоку, и он медленно
проступает из белого, как проявляется фотография. Так «Космос» передает
финал: третий спутник разворачивается объективом к Земле под фразой «Вышка
такая большая, что ее можно увидеть только со спутника», а из
вспышки сразу проступает снимок — доска со всеми цифрами страницы в рамке
видоискателя, с той же фразой подписью. Титульной карточки у финала нет,
чтобы между вспышкой и снимком не вставал лишний такт.

```js
export const meta = { id, title, subtitle, flash: true };
```

Вспышка одна и не мигает. Ведет ее `flashCurtain()` в `lib/stepper.js`, цвет —
токен `--flash`. Занавесом она приходит только вперед по тактам и только на
широком экране; назад, при переходе по полоске и при «меньше движения» блоки
сменяются как обычно.

**На телефоне о вспышке просит читатель.** Тактов там нет, историю ведет
прокрутка — а она не умеет ни остановиться на кадре, ни закрыть занавес.
Поэтому последний такт блока не снимает сам, а отдает кнопку: у «Космоса» это
«Сделать снимок» на самой картинке. Нажатие играет круглую вспышку на линзе —
ту же, что и на широком экране, — а следом блок посылает `story:flash`
(`root.dispatchEvent(new CustomEvent('story:flash', { bubbles: true }))`), и
каркас играет тот же занавес: экран белеет, страница за белым переходит к
следующему разделу, и он проступает из белого. Снимок — такое же положение
картинки, как поворот планеты: в `open()` его возвращают к «еще не сделан»,
и кнопка приходит снова.

**Отдельного движения колеса вспышка не просит.** Последний такт блока и
приход следующего — это одно движение: модуль играет свой шаг, и сразу за ним
закрывается занавес. Так снимок и вспышка не разваливаются на два такта. Такт
при этом наполовину принадлежит одному блоку, наполовину другому: полоска
сверху показывает уходящий раздел, пока идет анимация, и переключается на
следующий ровно тогда, когда экран белеет. Делает это `join()` в
`mountStepper`; занавес просит об этом полем `joins` в `CURTAINS`.

**Переходный экран (необязательно).** Модуль может встретить читателя одной
цифрой и одной строкой, которые уезжают влево, пока титульная карточка едет
справа:

```js
export const meta = {
  id, title, subtitle,
  lead: { value: '63 000+ студентов', text: 'Из них…' },
  intro: true
};
```

Работает и у сцены, и у обычной секции — но только вместе с `intro`, потому
что это одно движение: переходный экран сменяется титульной карточкой.

Переходный экран тоже может приходить по частям — так же, через
`<span class="intro-stage" data-stage="N">` внутри `lead.text`. Такт на каждый
номер, а не на каждый элемент: две части с одним и тем же `data-stage`
приходят вместе, одним движением колеса (так вопрос и шкала под ним встают на
экран разом). Нумеровать части нужно подряд, с единицы: номер — это и есть
очередь, и пропущенный номер забирает себе такт, на котором ничего не
происходит.

Часть может не только появляться, но и двигать соседей — по своему
`--lead-stage-N`, который каркас ведет от нуля к единице. Так у «Годов учебы»
ответ «912 лет потребуется…» не уступает места карточке года, а поднимается
над ней. Двигать при этом нужно саму коробку части (`.intro-stage`), а не
то, что внутри нее: каркас режет каждую часть по ее краю
(`overflow: hidden`), и уехавшая вверх строка просто пропадает — на экране
остается пустота там, где она была.

Высоту экрана каркас меряет в том состоянии, в котором тот выше всего: части
раскрыты, `--lead-away` в нуле, а все `--lead-stage-N` в единице
(`fitHeight()` в `lib/page.js`). Померенный на первом такте экран, который
растет к последнему, сжимался бы меньше, чем нужно, и вылезал бы за край окна
по дороге. Но и расти ему незачем: место, которое освободилось — у «Годов
учебы» это шкала, уже сказавшая свое, — отдается ровно в ту же долю такта,
и тогда сжатие не трогает остальные такты (`--swap-took` в `viz/study.js`).

Карточка работает и на узких экранах, но иначе: там залипает не вся секция
(сложенный в одну колонку блок выше экрана, его обрезало бы), а только сам
заголовок — он стоит по центру, потом уменьшается, встаёт к верхнему краю и
ждёт, пока снизу подъедет блок. За это отвечает обёртка `.viz-intro-hold`,
которую каркас рисует вокруг `.viz-header`.

**Карточка по частям (необязательно).** Если модуль объявляет
`introStages: 3`, титульная карточка не появляется целиком: сначала виден
заголовок и то, что не размечено, а дальше по прокрутке — по одной части за
экран. Части модуль размечает сам, в своём `subtitle`:
`<span class="intro-stage" data-stage="1">…</span>`. Каркас держит такой блок
закрытым, потом раскрывает его на нужную долю высоты; всё остальное (что
происходит с этими частями, когда карточка садится на место) — дело модуля,
через переменную `--intro-body`. Подзаголовок каркас кладёт внутрь `<p>`, так
что разметка в нём — только строчные элементы.

**Сцена (необязательно).** Если визуализация рассказывает историю по шагам,
она добавляет в `meta` число шагов и возвращает из `init` объект с `step`:

```js
export const meta = { id, title, subtitle, steps: 3, intro: true };

export function init(root) {
  function step(i) { /* i — номер шага, 0..steps-1 */ }
  return { step };
}
```

Каркас делает такую секцию липкой сценой: содержимое залипает, а прокрутка
внутри неё зовёт `step(i)`. С `intro: true` сцена начинается с того же
титульного экрана, что и первый блок. На экранах уже 860px сцена выключается и
`step(steps - 1)` вызывается один раз — модуль должен показать итоговое
состояние. Пример — `viz/stadium.js`: пустая арена, потом лицей и кампусы по
одному, последний шаг отдаёт стадион пользователю вместе с контролами.

**Шаг, который ждет читателя (необязательно).** Если блок о чем-то спрашивает,
следующее движение колеса не должно отвечать за читателя. Модуль возвращает из
`init` функцию `hold`:

```js
return {
  step,
  hold: (i, { quiet } = {}) => (i === 1 && guess === null ? (quiet || nudge(), true) : false)
};
```

Каркас спрашивает ее перед тем, как играть шаг `i`: `true` — движение не
проходит. С `quiet: true` спрашивают тихо, только чтобы узнать (так подсказка
внизу решает, молчать ли ей) — блок в этом случае ничего не показывает и не
подталкивает. Без `quiet` читатель сам попросил идти дальше, и тут уместно
показать, чего не хватает: подсветить полосу, мигнуть кнопкой. Когда ответ
получен, блок посылает `story:next` (`root.dispatchEvent(new CustomEvent(
'story:next', { bubbles: true }))`), и страница идет дальше сама. Так сделан
вопрос про страны в `viz/world.js`.

**Из вопроса всегда есть выход.** Рядом с кнопкой, которая отправляет догадку,
стоит вторая — «Показать ответ»: угадывать никто не обязан, а блок, который
держит такт до метки, иначе не пройти вовсе. Она не ждет метки и снимает
ожидание совсем (`skipped` в `viz/world.js` и `viz/study.js`): читатель
попросил ответ прямо, и подталкивать его после этого не к чему. Как только
метка поставлена, второй кнопки больше нет — обе делали бы одно и то же.

Так же умеет ждать и **часть переходного экрана** — для вопроса, который
задается до того, как блок пришел: `holdIntro(stage, { quiet })`, где `stage` —
номер из `data-stage` той части. Ждать умеют только части переходного экрана;
титульная карточка и все остальное в открытии — нет.

При переходе по полоске и при «меньше движения» вопрос пропускается: читатель
сразу видит ответ — там страница не играет историю, а просто показывает
итоговое состояние, и блок, застывший на вопросе, был бы единственным местом,
до которого она не дошла. На узком экране вопрос, наоборот, остается: там
страница листается пальцем, ответить по-прежнему можно, и отнимать у читателя
единственную угадайку не за что.

**Цифра переходит в следующий блок (необязательно).** Число, на котором
заканчивается блок, может не исчезать вместе с ним, а перелететь в
переходный экран следующего раздела, прокрутив по пути значение: «на 21 955
принятых студентов» становится «~22 000 первокурсников», «77 649 мест» —
«63 000+ студентов». Модуль называет элемент со своим итоговым числом:

```js
export const meta = { id, title, subtitle, handoff: 'filled' };  // data-el
```

Место посадки размечать не нужно: переходный экран — это одна цифра и одна
строка, и каркас берет первое число в `lead.value`. Работает только на
широком экране, только вперед по тактам и только если у следующего раздела
есть переходный экран с числом.

**Картинка переходит в следующий блок (необязательно).** Кроме числа блок
может отдать картинку: переходный экран следующего раздела тогда стоит над
ней. Так стадион вырастает на экран под вопросом «Флагов»: студенты на своих
местах одним цветом, иностранцы — кучкой внутри своего кампуса.
Модуль объявляет в `meta` поле `carry: true` (по нему каркас сразу ставит
переходный экран следующего раздела наверх, освобождая место под картинку) и
возвращает из `init` поле `carry`:

```js
export const meta = { id, title, subtitle, carry: true };

return {
  step,
  carry: {
    from: canvas,             // где картинка сейчас
    box: () => ({ x, y, w, h }),   // где она внутри этого холста
    paint: (target) => box    // нарисовать ее такой, какой она переходит, в любой холст
  }
};
```

Каркас рисует картинку заранее, пока читатель смотрит текущий блок, во весь
экран под переходным экраном следующего раздела. На такте прихода она
вырастает туда из `from` за то же время, что едет страница, и перекрашивается
на лету. Когда переходный экран уходит, картинка тает вместе с ним
(`--lead-away`), а строки переходного экрана на это время получают белые
плашки, чтобы читаться поверх нее. Цвета «все студенты» и «иностранцы» — токены
`--students` и `--foreign`. Работает только на широком экране и только если у
следующего раздела есть переходный экран.

**Блок открывается с начала (необязательно).** Если в блоке что-то идет само —
поезда едут по кольцу, планета крутится, автобусы развозят город, — читатель
должен увидеть это с начала: первый поезд приходит справа, Земля повернута
кампусами к нам. А картинка собирается задолго до того, как до нее дошли, и
продолжает идти, пока читатель в других разделах. Поэтому модуль возвращает из
`init` функцию `open`:

```js
return { step, open() { epoch = performance.now(); } };
```

Каркас зовет ее каждый раз, когда блок выходит на экран: на такте, который его
открывает (у блока с титульной карточкой — на том такте, где она садится и
картинка видна, а не раньше), при возврате шагом назад из следующего раздела и
при переходе по полоске сверху. На узком экране — когда секция въезжает в поле
зрения и когда читатель в нее переходит. Одного въезда там мало: секция ростом
в несколько экранов с экрана и не уходила, и шаг назад из следующего раздела
возвращал читателя туда, где он блок бросил. **Зовут ее не один раз**, и
позвать дважды должно значить ровно то же, что позвать один раз: это не
событие, а «верни картинку в начало».

Возвращать нужно только то, что идет само — но на телефоне к этому относится и
прокрутка списка внутри блока. Стена профессий листается пальцем, и место, на
котором ее бросили, — такое же положение картинки, как поворот планеты:
вернувшись в раздел, читатель застает ее с первой строки (`open()` в
`viz/professions.js`). Состояние истории каркас
восстанавливает сам — через `step(i)`, который вызывается следом. Если на узком
экране блок показывает итоговое состояние (`step(steps - 1)`), историю в `open`
трогать нельзя: модуль смотрит на ширину сам, как это делает `viz/space.js`.

**Каждый такт что-то меняет.** Один такт — одно движение колеса, и читатель
вправе увидеть за него новый кадр. Если модуль показывает свой первый шаг сразу
(как стадион — пустой ареной: иначе в момент, когда блок проявляется, мелькнёт
не тот кадр), он объявляет `opensOnStep: true`. Тогда каркас сам ставит блок в
`step(0)`, пока секция въезжает, а такты сцены начинает со следующего шага —
иначе первый «дальше» пришёлся бы на картинку, которая и так на экране.

Если сцена меняет состояние, которым можно управлять руками, при первом же
клике по контролу управление отдаётся пользователю и `step()` перестаёт
перебивать его выбор.

**Ход по телефону.** Единственное движение по странице: один такт за один мах
пальцем, чем бы этот такт ни был. Каркас знает три их вида и всегда ведет к
ближайшему — части открытия (их границы публикует `stops()` у открытия),
состояния истории внутри блока (`ahead()` у модуля) и начало следующего
раздела. Где тактов впереди нет — хвост со списком профессий, лента лет,
переключатели — ход листает ровно по экрану и доводит до конца страницы.
Больше 2,2 экрана за раз не уходит.

Ход у всех один: палец, колесо, клавиши. Кнопки в углу нет — мах пальцем и так
играет ровно один такт, а кнопка повторяла его же и занимала угол. Что страницу
листают, говорит обычная подсказка внизу («Листай»), она же на широком экране.

**Любое касание стоит один такт.** Длина маха не значит ничего: и мах на
полэкрана, и движение в двадцать пикселей, и стук по экрану на месте — это
один такт, не больше и не меньше. Мах в сорок пикселей раньше не значил ничего
вовсе, а палец на телефоне у всех разный: кто-то ведет страницу, кто-то
постукивает по ней. Куда идти, говорит направление, если палец успел его
показать; стук на месте ведет вперед. Мах длиной от `TAP_PULL` играет свой
такт сразу, под пальцем, короткий — когда палец отпустили. В узком окне на
столе то же самое делает клик мышью.

Не касается это того, у чего свое дело: кнопок, ссылок, переключателей,
ползунков, полоски разделов и коробок со своей прокруткой (`РУЧКИ` в
`lib/stepper.js`). Тап по переключателю меняет кампус и остается на месте —
иначе он уводил бы со страницы, на которой читатель его нажал. Блок, который
рисует свой контрол не кнопкой, а строкой с `data-value`, попадает в это
правило сам; что-то совсем свое нужно внести в `РУЧКИ`.

**Но ручка, которой еще нет на экране, касания не берет.** Переходный экран
весь click-through, кроме кнопок, полей и ползунков: экран летит поверх
страницы и иначе съедал бы все под собой, а спросить читателя он вправе.
Беда в том, что часть, которая еще не пришла, место под себя уже держит — у
«Годов учебы» шкала с кнопкой это полторы сотни пикселей пустоты над
вопросом, которого на экране нет. Палец, опущенный туда, попадал в невидимую
шкалу, каркас считал касание ручкой, такт пропадал, и читателю приходилось
стучать по экрану второй раз. Поэтому каркас вешает на часть, которая еще не
пришла, класс `is-shut` (`paint()` в `lib/page.js`), а `layout.css` по нему
отнимает у ее контролов касания. Модулю делать ничего не нужно.

**Картинка, которую крутят рукой (`page-turns`).** Шар «Космоса» поворачивается
пальцем — но палец ему достается только поперек экрана: вдоль ведут страницу, и
отнять это нельзя, картинка занимает полэкрана и листать было бы нечем. Блок
ставит класс на то, что крутится (у «Космоса» — на сам холст), и каркас на
поперечное движение по нему такта не играет (`вертят()` в `lib/stepper.js`).
Решает первое же движение, и дальше палец принадлежит тому, кого выбрал:
ведущая поперек рука к концу дуги идет вниз, и страница прыгала бы с середины
поворота. Стук по такой картинке по-прежнему стоит такт, а мыши она достается
целиком — клик по ней страницу не ведет. Сам поворот блок ведет своими
указателями (`pointerdown`/`pointermove`), и палец берет картинку не сразу, а
когда стало видно, куда он идет.

Четвертая остановка — низ блока, но только у того, который в экран не влез:
переключатели под картинкой на тесном телефоне иначе терялись — ближайшей
границей оказывалось начало следующего раздела, и ход уходил туда через их
голову. У блока, который умещается, низ приезжает раньше верха, и отдельная
остановка на нем была бы тактом на три десятка пикселей. По той же причине
границы, разошедшиеся меньше чем на `ОСТАТОК`, каркас считает одним местом и
берет дальнюю: низ длинного блока и начало следующего раздела расходятся ровно
на поля секции, и врозь они давали такт, на котором ничего не происходило.

У блока с липкой сценой из-за этой остановки бывает белая полоса сверху.
Сцена едет своим путем, а за ней лежит хвост — то, что блок показывает, когда
отдает себя читателю. Хвост ниже экрана — и низ блока оказывается ближе верха
хвоста: ход останавливается, не довезя сотню пикселей, и хвост приходит с
пустотой над собой. Обе границы — одно место, когда хвост ровно в экран, так
что недостающее отдают картинке; мерить это нужно живьем, по окну, — высота
карточек, переключателей и городов набирается фиксированными пикселами, и доля
экрана то не добирает, то вылезает (`fitTail()` в `viz/area.js`). Хвост выше
экрана ничего не ломает: низ блока лежит дальше, ход приводит сначала к хвосту,
а остаток читается следующим тактом.

**Такт не кончается в пустоте.** Между блоками лежит полоса, на которой читать
нечего: прошлый блок уже уехал вверх, а переходный экран следующего раздела еще
прячется — он прибит к окну и показывается только с приходом своей секции. Такт,
кончившийся там, выглядит сломанной страницей: белый экран и край чужой картинки
сверху. Поэтому ход, доехав, смотрит, занято ли на экране хоть что-нибудь —
тело блока, переходный экран, заголовок, шапка или подвал (`видно()` в
`lib/stepper.js`), — и если нет, доигрывает такт до конца сам, в ту же сторону.
Доезд один на такт: если и после него смотреть не на что, страница стоит, а не
скачет дальше сама.

Занято — это пятая часть окна, а не точка ровно посередине. Серединой мерилось
до тех пор, пока не нашелся экран, на котором смотреть есть на что, а середина
пустая: титульная карточка паркуется у верхнего края, и на высоком окне ее
нижний край до середины не достает. Такт, который приводил очередную часть
карточки, выходил «пустым», ход доигрывал его дальше — и часть пропадала
целиком: у метро после электробуса страница уезжала сразу к переключателям,
через голову вагонов.

Пятой части не просят только у карточки, которая держит экран. Заголовок с
подзаголовком посреди пустого поля — это две строки, девяносто пикселей из
семисот: «Вышка — просто космос!» не набирал нужной доли, такт с ним считался
пустым, ход доигрывал его сам — и заголовок проскакивал, читатель видел фразу
про орбиту, а следом сразу планету. Но карточка посреди экрана — это и есть то,
ради чего такт делался, сколько бы места она ни занимала. Севшая в шапку —
другое дело: там она край уехавшего блока и считается как все.

Попасть в эту полосу настольный браузер не дает — в тактах она не лежит. А
айфон дает: высота окна там ходит вместе с панелью Safari, и вся арифметика
положений считается по числу, которое в этот момент меняется.

**Своя прокрутка внутри блока (`page-scrolls`).** Прокрутка на телефоне отнята
у всей страницы — но не у того, что блок пометил классом `page-scrolls`. Так
листаются стена профессий и стена флагов: содержимого там на несколько экранов,
а резать его краем нельзя — это и есть ответ блока. Класс ставится на саму
коробку с прокруткой, и каркас отпускает страницу, когда она доехала до своего
края (`свое()` в `lib/stepper.js`). Такой коробке нужна высота: не `flex`, а
отмеренная руками — колонка, ужатая ниже своего содержимого, не прокручивается,
а налезает на то, что под ней. И место, на котором коробку бросили, — такое же
положение картинки, как поворот планеты: в `open()` ее возвращают к началу —
через `toTop()` из `lib/ui.js`, а не простым `scrollTop = 0`.

Простого обнуления на айфоне не хватает. Мах пальцем оставляет после себя
инерцию: коробка едет еще полсекунды после того, как палец отпущен, а такт,
на котором блок открывается, едет семьсот миллисекунд — ноль, записанный в это
время, инерция перетирает обратно, и читатель застает стену там, где ее
бросил. `toTop()` обрывает инерцию (`overflow: hidden` на один кадр снимает
коробку с ускоренного слоя) и держит ноль, пока идет такт, — но отпускает
сразу, как только читатель тронул коробку сам. На столе ничего этого не видно:
там прокрутка кончается вместе с движением, и обе версии ведут себя
одинаково.

**Посадка карточки и приход блока — один такт.** Карточка садится на свое место
в шапке, а блок под ней начинается ниже экрана: чтобы увидеть его целиком,
нужен был еще один ход, на котором только и происходило, что уезжала шапка.
Поэтому последняя остановка открытия — не конец зоны, а верх `.viz-body`
(`stops()` в `lib/page.js`): карточка садится по дороге, и блок приезжает
собранным. Работает это только потому, что зона парковки шапки
(`--intro-hold`) считается по севшей высоте заголовка, а не по той, что у него
на раскрытой карточке: иначе зона сжималась бы с каждым кадром посадки, блок
ехал бы вверх вместе с ней, и такт промахивался бы мимо на две сотни пикселей.

Блок отвечает на один вопрос — сколько пикселей до следующего состояния:

```js
return { step, ahead: () => stepAhead(gone, span, parts, share) };
```

`stepAhead()` из `lib/ui.js` считает это за блок: `gone` — сколько пути уже
позади, `span` — сколько его всего, `parts` — на сколько отрезков нарезана
история, `share` — какая доля пути ей принадлежит (блок, который отдает себя
читателю, оставляет на это последнюю часть). Ноль значит «впереди ничего»:
блок еще не вышел на экран или история рассказана — тогда ход уходит дальше,
к следующему разделу. Если
отрезки неравные, как у финала, блок отвечает сам, по тем же порогам, по
которым ведет историю.

**Назад блок спрашивают отдельно** — `behind()`, по тем же правилам:

```js
return { step, ahead: () => …, behind: () => … };
```

`ahead()` считает только вперед, и то же число, взятое назад, уводит ход мимо
состояния. А без своего числа назад остаются одни границы разделов, и шаг
назад из вопроса про площадь уносил через всю историю: поля, пятиэтажки и
город проносились за одно движение. Блок, который назад отвечать не умеет,
листается как и раньше, экраном.

Двигает страницу каркас руками, а не `behavior: 'smooth'`: блок на передаче
себя читателю меняет собственную высоту, браузер отвечает на это сдвигом
прокрутки, и плавный скролл от такого сдвига отменяется.

**И ставит ее туда, куда идет такт, а не двигает на столько-то пикселей.**
Разница видна только на айфоне: прокрутка там живет на своей стороне, и сдвиг
«на столько-то» иногда пропадает целиком — следующим кадром страница
возвращается туда, где была. За такт так терялось два-три десятка пикселей:
ход вставал между остановками, карточка застывала с полураскрытой строкой
посреди слова, а шаг назад не доходил до начала. Поставленное место потерю
переживает — следующий кадр ставит то же самое снова. А место, *откуда* такт
идет, едет вместе со страницей: блок, который на приходе складывает свои
цифры, меняет высоту, браузер отвечает на это сдвигом прокрутки — и этот сдвиг
нужно отдать странице, иначе один такт превратится в три. Ведет это `glide()`
в `lib/stepper.js`.

**Чтение кадрами на телефоне (`taps: true`, у стадиона и флагов).** Широкая
версия — не скроллителлинг, а машина тактов: одно движение колеса — один кадр,
страница при этом неподвижна. Прокрутка передает это с потерями: на кадр
приходится две-три сотни пикселей, а мах пальцем — семьсот, и три кадра
пролетают за одно движение, обрывая анимацию друг друга.

Блок, объявивший `taps: true`, на телефоне читается так же, как на широком
экране: страница останавливается на нем, касание играет следующий кадр
целиком, и `step()` зовет каркас, а не прокрутка. Когда история
рассказана, страница отпускается — дальше блок отдан читателю, и его список
или контролы листаются обычной прокруткой.

Выход не закрыт никогда: тяга вниз на первом кадре отпускает страницу назад,
последний кадр отпускает ее вперед, полоска сверху по-прежнему ведет в любой
раздел. Страницу держит `position: fixed` на `body`, а не съеденные касания:
мах, уже отпущенный пальцем, иначе не остановить. Ловится блок по своему телу
(`.viz-body`), а не по секции: секция начинается с открытия, а открытие
читается прокруткой, как и все, что не история.

Модулю нужно: объявить `taps: true`, не вешать свою прокруточную историю на
телефоне и отдать каркасу настоящий `step` (а не пустышку, как в режиме
прокрутки). При «меньше движения» режим выключается — там читателю показывают
итоговое состояние, и отнимать у него прокрутку было бы ровно обратным тому,
о чем он попросил.

**Блок с вопросом на телефоне читается только кадрами.** Прокрутке нечем
придержать читателя: `hold` она не спрашивает, своих остановок внутри блока
нет, и один мах пальцем уносил с карточки с догадкой прямо в следующий
раздел — через голову всего, что блок показывает в ответ. Так пропадала вся
стена флагов: читатель видел вопрос и следующий раздел, а ответа не видел,
если не догадывался нажать кнопку. Кадрами же страница останавливается на
блоке, вопрос придерживает ход, а с ответом блок отдает себя читателю.
Поэтому блок, у которого есть `hold`, на телефоне объявляет и `taps: true`.

**Такт длиннее обычного (необязательно).** Все такты идут по 700мс. Шаг, на
котором играет что-то длиннее — поворот истории, долгое движение, — говорит об
этом сам, через `span(i)` в объекте из `init`:

```js
return {
  step,
  span: (i) => (i === 3 ? 1600 : 0)   // мс; 0 — обычный такт
};
```

Каркас ждет столько, сколько попросили, и не пускает следующее движение колеса
поверх анимации. Дольше 2500мс не бывает: после этого читатель уже ждет
страницу, а не смотрит на нее. Назад шаг отыгрывается с той же длительностью.

**Клавиша нажимает то, на чем стоит фокус.** Страница слушает колесо и
стрелки, а пробел и Enter отдает контролу, если фокус на нем: иначе тумблер,
до которого читатель дошел табом, нельзя было нажать — страница съедала
нажатие и уходила дальше. Стрелки в этот момент по-прежнему листают, а у
ползунка (`role="slider"`) они свои.

**Клавиатура не уходит из текущего раздела.** Все секции лежат в документе с
самого начала, а читателю показывают одну. Поэтому при чтении тактами каркас
держит на всех остальных атрибут `inert`: Tab не уводит в контролы блоков,
которые уже прочитаны или еще не открыты, и экранный диктор не читает их
раньше времени. Модулю делать ничего не нужно — его контролы оживают, когда
раздел на экране. Так же выключены титульный экран и подпись об
источнике: они не секции, но они тоже за краем экрана, и первый же таб из
блока уводил фокус на ссылку в заголовке — а браузер прокручивал страницу к
ней, против такта, на котором она стояла. При «меньше движения» и на узком
экране, где страница листается обычной прокруткой, ничего не выключается.

**Упавший такт страницу не роняет.** Каркас ждет, пока такт доиграет, прежде
чем снова слушать колесо, — поэтому исключение внутри модуля могло бы оставить
страницу висеть навсегда. Все вызовы в модуль обернуты (`tried()` в
`lib/stepper.js`): падение попадает в консоль строкой «Такт … упал, страница
читается дальше», такт считается доигравшим, чтение продолжается. Картинка с
этого момента может быть неверной, так что ошибка в консоли — не мелочь, но
читатель хотя бы не упирается в мертвую страницу.

**Полоска сверху не ждет анимацию.** Читатель, выбравший другой раздел, просит
о нем прямо сейчас — а такт идет до двух с половиной секунд, и все это время
страница раньше не отвечала вовсе. Теперь идущий такт обрывается: поколение
тактов растет (`cut()` в `lib/stepper.js`), кадры прошлого такта перестают
рисоваться, его `done` не отпускает страницу, а занавес, под которым его
застали, снимается — о нем сказано через `onCut()`. Доигрывается оборванный
такт тут же: прыжок и так собирает все блоки до цели в том состоянии, которым
они кончаются, так что прерванный приходит к своему концу, просто мигом. То же
и у возврата на обложку. Модулю делать ничего не нужно: его `step()` зовут с
нужным номером, как и всегда.

**В прочитанную главу страница приводит ее итогом.** Смотреть заново то, что
уже видел, читатель не просил — он просил эту главу. Поэтому прыжок по полоске
в раздел, который уже прочитан, ставит страницу не на первый его такт, а на
последний (`ends[]` в `mountStepper`; такт на двоих в итог не годится — он
уводит в следующий раздел). На телефоне то же самое мерится прокруткой:
страница целится в последний экран раздела, а блок ставится в свое последнее
состояние. Непрочитанная глава по-прежнему открывается с начала.

Чтобы сыграть ее заново, у нижнего края появляется «Смотреть сначала»
(`.page-replay` в `index.html`, поле `replay` у `mountStepper`). Кнопка уходит
с первым же тактом: дальше читатель читает, а не возвращается. Лежит она вне
шапки — при чтении тактами шапка выключена целиком (`inert`), и кнопка в ней
была бы недоступна ни мыши, ни клавише.

Каркас в `index.html` создаёт секцию, шапку и `.viz-body`, затем зовёт `init`.
Чтобы добавить визуализацию: написать `viz/<name>.js`, импортировать его в
`index.html` и добавить в массив `MODULES`.

Модуль не знает о соседях, не трогает `<body>`, не пишет в глобальные
переменные и не добавляет свои стили в `styles/` — только в собственный файл,
если без этого никак.

**Что каркас рисует до сборки блока, должно жить без стилей блока.** Заголовок,
подзаголовок и переходный экран каркас ставит на страницу сразу, а `init`
зовет позже — значит, в момент, когда карточка уже играет, стилей модуля еще
нет: они приезжают внутри `.viz-body` вместе с блоком. Разметка в `title`,
`subtitle` и `lead` должна выглядеть правильно и без них — инлайновым стилем
или тегом `<style>`, который едет прямо в этой строке. Такой `<style>` каркас
из заголовка выбросит, когда будет брать оттуда название раздела для полоски
сверху, — писать в нем можно спокойно.

Иначе ловушки тихие и плавающие, потому что `prepare()` иногда успевает
собрать блок заранее, а иногда нет. Части карточки (`intro-stage`), которым
`display: block` задан из стилей блока, остаются строчными — расти им нечем,
и они появляются рывком в конце такта. Переходный экран, у которого перенос
строки задан стилями блока, каркас обмеряет как одну длинную строку, решает,
что она не влезает, и уменьшает весь экран.

## Правила

**Цвета.** Только токены из `tokens.css`. Цвета городов берутся из `data/hse.js`
(они нужны и в canvas, где CSS-переменных нет) — не дублировать их руками.
У города два оттенка: `c.color` — основной, `c.colorLight` — тот же цвет
светлее (на стадионе им закрашены сотрудники). Светлый считается из основного
через `tint()` из `lib/color.js`, руками его прописывать не нужно.

**Данные.** Все цифры про людей — из `data/hse.js`. Оттуда же `YEAR` — год, за
который эти цифры верны; подпись в подвале пишется из него, а не руками в
разметке. Отсчет лет назад — другое утверждение: он идет от сегодняшнего дня
(`viz/study.js`), потому что события в `data/history.js` написаны под
подвижный старт и карточка сама говорит, насколько ближайшее из них
отстоит. Смешивать эти два года не нужно. Цифры про объект сравнения
(вместимость арены, длина вагона) живут в самом модуле.

**Числа.** `nf()` для разрядов, `pct()` для процентов с запятой, `plural()` для
склонений. Никакого `toLocaleString` в модулях напрямую.

**Разделитель «·» не используется** — ни в подписях, ни в карточках, нигде.
Вместо него тире с пробелами (когда вторая часть поясняет первую: «77 649 из
81 000 — 95,9%») или запятая (когда это перечисление: «16 803 принятых,
102 вагона»).

**Разметка.** Общие компоненты — из `layout.css`: `.col-left` / `.col-right`,
`.kind-row`, `.city-card`, `.toggle`, `.btn`, `.meter-card`, `.canvas-card`.
Не изобретать свои варианты тумблера или карточки.

Тумблеру (`<button class="toggle" role="switch">`) имя и состояние каркас
проставляет сам — `nameSwitches()` в `lib/ui.js`, вызывается после сборки
блока: имя берется из строки, в которой тумблер стоит, состояние следует за
классом `on`. Модулю делать ничего не нужно; если строка объясняет плохо,
модуль пишет свой `aria-label`, и его не трогают.

**Подпись об источнике** — одна на всю страницу, в `<footer class="page-footer">`
в `index.html`. Модули её не рисуют.

**Элементы внутри модуля** ищутся через `data-el="..."`, не через `id` —
на странице несколько модулей, идентификаторы столкнутся.

**Низ экрана занят.** Подсказка о том, как читается страница, стоит у нижнего
края и возвращается всюду, где читатель замешкался, — не только на титульном
экране. Поэтому полоса `--hint-room` внизу секции ей и принадлежит: она вычтена
из высоты секции в любом режиме чтения — и тактами, и прокруткой, — и блок до
нее не достает. Модулю делать
ничего не нужно — верстать по `.viz-body`, высота которого уже без этой полосы.
Переходный экран, который оказался выше оставшейся комнаты, каркас уменьшает
целиком (`--lead-squeeze`), чтобы он помещался, а не уходил за край.

**Мобильные.** Адаптив уже в `layout.css` (брейкпоинты 860px и 400px): до
860px колонки складываются в одну, `.col-right` уезжает наверх и залипает,
`.col-left` скроллится под ним. Модулю ничего делать не нужно — достаточно
использовать `.col-left` / `.col-right` и общие карточки. Свои медиазапросы
писать только под то, что специфично именно для этой визуализации.

Ниже 860px страница **не прокручивается вовсе**: читатель ведет ее тактами —
махом пальца, колесом или клавишами, — а каркас двигает ее сам и всегда до
границы кадра. Прокрутка отобрана у браузера
(`touch-action: none` плюс `preventDefault` на жестах), потому что мах пальцем
отматывал по три состояния разом и останавливался посреди движения: угадать,
где кончился кадр, было нельзя. Свое остается тому, что само умеет
прокручиваться, — списку разделов, который открывается касанием полоски.

Позиция страницы при этом по-прежнему обычная прокрутка, просто двигает ее
только каркас: вся арифметика положений, липкие картинки и ленивая сборка
блоков работают как работали. За это отвечает `mountScrolled()` в
`lib/stepper.js`; выбор режима делается один раз при загрузке. При «меньше
движения» на широком экране прокрутку не отнимают: там просили меньше движения,
а не меньше управления.

**Складной телефон раскрывают посреди чтения.** Ширина переходит границу в
860px, а две машины чтения нельзя поменять под читателем — страница читается
заново. Но начинается она не с титульного экрана: номер раздела переживает
перезагрузку в `sessionStorage` (`keep()` и `kept()` в `lib/stepper.js`), и
машина, которая поднялась следом, сразу идет к нему. Так же в обратную сторону:
сложили — страница перечитывается узкой с того же раздела. Раздел берется не в
момент раскрытия, а из последней отрисовки: спрошенная после того, как ширина
уже сменилась, страница отвечает по новой геометрии, и читатель с середины
читается как дочитавший.

Раскрытие, которое границу не переходит (466 → 626 у iPhone Duo), машину не
меняет и страницу не перезагружает — но блоки становятся другой высоты, а
прокрутка остается прежним числом пикселей. Поэтому каркас возвращает читателя
на ту же долю пути внутри его раздела: история на узком экране рассказывается
долей пройденного, так что та же доля новой высоты — то же место в истории.
Отвечает только ширина: высота меняется всякий раз, когда уезжает панель
браузера, и двигать страницу под читателем из-за этого нельзя.

Блок на узком экране собирается, когда читатель к нему подходит, титульная
карточка следует за своим положением, а сцена без `taps` показывает итоговое
состояние (`step(steps - 1)`) и отдает управление читателю.

**Открытие на телефоне стоит вдвое меньше прокрутки** (`ZONE_NARROW` в
`lib/page.js`). На широком экране каждая часть открытия — такт, одно движение
колеса; на телефоне тот же счет превращался в экран пальца на каждую, и
переходный экран с вопросом стоял неподвижно два экрана подряд. Играет все то
же самое, просто просит вдвое меньше пути.

**Подзаголовок на телефоне живет, пока держится карточка.** Четыре-пять строк
между заголовком и картинкой — это треть экрана, и уходить они не собирались:
прочитаны они были на титульной карточке, где в них весь смысл и где под них
отдан целый экран. Поэтому на узком экране подзаголовок складывается вместе с
карточкой, по той же `--intro-body`. Высоту каркас меряет сам и кладет в
`--sub-h` (`measure()` в `lib/page.js`) — у текста нет высоты, от которой можно
отнять. Меряется она на раскрытой карточке, где подзаголовок стоит в 1/k ширины
и переносится чаще, то есть выше всего. Касается это только секций с открытием:
у блока без карточки подзаголовок негде было бы прочитать, и он остается на
месте. Модулю делать ничего не нужно — но и рассчитывать на то, что
подзаголовок будет виден рядом с картинкой, на телефоне больше нельзя: все, что
должно остаться на экране, блок говорит внутри себя.

Высота эта только обрезает подзаголовок сверху (`max-height`), а своя у него —
по тому, что на нем сейчас. Прибитый к полной высоте, он держал на карточке
метро три сотни пикселей пустоты под единственной строкой: карточка выходила в
целый экран, центрировать ее было нечем, и заголовок с одной строкой под ним
вставал у верхнего края. На складывание это не влияет — складываться
подзаголовок начинает, когда все части уже пришли, и в этот момент его своя
высота и есть `--sub-h`.

**Карточка на телефоне стоит по центру того, что на ней сейчас.** На широком
экране ее центруют по высоте раскрытой карточки — иначе заголовок дергался бы
вниз с приходом каждой части. На телефоне наоборот: части приходят тактами, и
карточка растет от середины — каждая новая строка раздвигает ее в обе стороны,
а не прибивает верх к краю экрана. Считается это живьем, по `.viz-header`
(`titleCard()` в `lib/page.js`).

**Блок на телефоне проявляется не раньше, чем карточка уберется с его пути.**
Зона парковки шапки (`--intro-hold`) считается по севшей высоте заголовка —
иначе такт промахивался бы мимо верха блока, — а на карточке заголовок в
полтора раза крупнее, и увеличен он трансформацией, которая в раскладке не
занимает ничего. Значит, на карточке заголовок висит над началом блока. Пока
блок прозрачен, это никому не мешает; но на ровной доле он проявлялся как раз
в эти кадры, и «Стадион заполнен на 0%» ложилось поверх «„Лужники“ — самая
крупная арена». Поэтому на узком экране блок ждет, пока карточка не сядет
больше чем наполовину (`.viz-intro .viz-body` в конце `layout.css`): к этому
моменту подзаголовок уже сложен, а заголовок вернулся почти в свой кегль. На
широком экране этого не нужно — там блок до своего прихода стоит ниже сгиба и
проявляется по дороге вверх.

**Переходный экран на телефоне меряется по окну, а не по секции.** Там он
прибит к окну (`position: fixed`), и вылезает не коробка, а содержимое —
сверху и снизу. `--lead-squeeze` считается от высоты окна и от размаха детей;
секция тут ни при чем, она в тысячи пикселей высотой.

**Строка меряется там, где встанет.** Цифра переходного экрана, которая почти
влезает в строку, не переносится, а уменьшается (`--lead-fit`, `fitLine()` в
`lib/page.js`). Решение это принимается по двум числам — ширине коробки и
длине строки, — и оба к моменту мерки держат что попало: коробка у сжатого
экрана шире окна (`--lead-squeeze` расширяет ее и возвращает назад
масштабом), а кегль только что перебирала подгонка карточки. Померенная в
кегле 1,05 строка влезала в одну и получала запрет на перенос — а вставал
экран в 1,55, и «На стадионе 63 000+ студентов» уезжало за правый край.
Поэтому мерят в несжатой коробке и в том кегле, в котором экран встанет:
коробка от сжатия только шире, а кегль от посадки карточки только мельче, так
что обе мерки берутся по самому тесному для строки состоянию. У экрана,
который паркуется, на широком кегль записан в стилях числом — мерить нужно
по нему.

**На телефоне подмена идет вверх, а не вбок.** На широком экране переходный
экран уезжает влево, а титульная карточка приходит справа: это смена кадра,
страница при этом неподвижна. На телефоне страница под пальцем, и то же самое
читается так, будто ее листают вбок, — единственное движение поперек хода.
Поэтому на узком экране экран уходит вверх, а карточка поднимается снизу на
его место, как у `exit: 'up'`. Модулю делать ничего не нужно: это общее
правило для всех переходных экранов, кроме тех, что паркуются (`exit: 'top'`)
— у них карточка не приезжает вовсе.

**Переходный экран с `exit: 'top'` паркуется и на телефоне.** Такой экран не
уезжает, а поднимается к верхнему краю и остается там: он и есть заголовок
блока — на широком экране карточка с заголовком в этом случае так и ждет за
правым краем и не приезжает вовсе. На телефоне парковка раньше была
выключена, экран уезжал вбок как обычный, и фраза пропадала за экран до того,
как приезжала картинка, про которую она сказана: «Но есть 196 зданий. А это
уже целый город» и город из этих зданий должны стоять вместе.

Высоту, которую занял припаркованный экран, каркас публикует в `--lead-hold`:
то, что блок прибивает к верху, прибивается под ним, а не за ним. Общее
правило делает это для `.col-right`; блок со своей липкой сценой читает
`--lead-hold` сам. Когда блок отдает себя читателю, место наверху нужнее
управлению — блок ставит на секцию класс `lead-gone`, и припаркованный экран
уходит; какой это раздел, говорит полоска сверху.

**Припаркованный экран не меняет кегль.** Обычный переходный экран набран от
`--intro-k` — того самого множителя, с которым едет титульная карточка: он
начинается с крупного и садится в единицу, и экран уезжает, пока карточка
приходит на его место. У парковки карточки нет, уходить экрану некуда, и тот
же множитель означал бы, что заголовок блока мельчает у читателя на глазах
посреди такта. Поэтому у `exit: 'top'` кегль берется от `--intro-k-big` — это
начальное, крупное значение того же множителя, и за такт оно не двигается
(`paint()` в `lib/page.js` публикует его рядом с `--intro-k`). На широком
экране так было с самого начала, просто множитель там написан числом.

**На парковке от экрана остается не все.** Припаркованный экран — заголовок
блока, и строке, которая была нужна только на самом экране, наверху места нет:
у «Зданий» это «Для расположения всех студентов и сотрудников у Вышки нет
своего стадиона (пока)» — шутка, договаривающая прошлый раздел, четыре строки
высотой. На телефоне она отнимала у города треть экрана, и он сжимался в
полосу посередине. Такую строку блок складывает сам, по `--lead-away`: ноль —
экран на месте, единица — он наверху. Высоту для этого блок меряет тоже сам
(у текста ее нет, отнимать не от чего) и кладет в свою переменную — см.
`measureLead()` в `viz/area.js`. Складывается строка плавно, вместе с тактом:
такт отыгрывается не мгновенно, и в любой его точке картинка должна быть
верной.

Высоту парковки каркас меряет живьем, по размаху детей экрана, так что
`--lead-hold` уменьшается сам и освободившееся место достается картинке.
А вот подгонку экрана по высоте (`--lead-squeeze`) каркас делает на полном его
росте: `fitHeight()` на время мерки ставит `--lead-away` в ноль — так же, как
раскрывает части. Померенный на полпути, экран вышел бы низким, сжимать его
было бы нечего, и вернувшийся назад читатель застал бы его обрезанным по краям
окна.

**То, что прибито к окну, прячется вместе со своей секцией.** Переходный экран
виден только пока его секция на экране: брошенный на полпути, он остался бы
висеть поверх всех следующих блоков до конца страницы.

Но спрашивать это с точностью до пикселя нельзя. Прокрутка на айфоне дробная:
верх секции и в спокойном состоянии стоит на треть пикселя ниже окна, а ход,
доехав, попадает в эту долю как придется. Промах на пиксель вниз прятал экран
целиком — такт кончался пустотой, каркас доигрывал его сам (`видно()` в
`lib/stepper.js`), и открытие приходило к читателю сразу со своей первой
частью: «Все эти здания нужны…» и 127 квадратов бакалавриата одним движением.
Поэтому секция считается пришедшей с допуском — `ДОПУСК` в `lib/page.js`, те
же 24 пикселя, что и `ОСТАТОК` у хода: то, что разошлось меньше чем на это,
страница и так считает одним местом.

**Кнопок «Снять все» и «Вернуть все» на телефоне нет.** Четыре города в два
ряда — это два движения пальцем, а строка кнопок стояла у самого низа блока,
там, где места меньше всего. Выключены они стилями (`.actions` в конце
`layout.css`), а не разметкой: на широком экране они на месте, и модулю не
нужно знать, какой сейчас экран. Освободившаяся полоса отдана картинке —
поездам, полям, арене, стене флагов, году и ленте лет; если блок рисует свою
полосу управления, место под нее он считает без кнопок.

**Палец — не курсор.** Цель меньше 24 пикселей по любой стороне на телефоне
не годится; у строки видов было 19. Размер при этом растет у области нажатия,
а не у того, что видно: переключатель остается 51 на 31, как у самих
телефонов. Правила в конце `layout.css`, селектором из двух классов — стили
блоков приезжают позже общих и иначе перебивают их.

**Наведение спрашивают, отклик на нажатие пишут сами, выделение снимают.**
Страница одинаково читается на айфоне и на андроиде, и то, что оставлено
браузеру, на них разное.

Курсор уходит с элемента сам, палец — нет: на тач-экране обе системы
оставляют последнее касание наведенным, пока читатель не тронет что-то
другое. Полоска разделов от этого стояла раздутой до конца чтения, нажатый
раздел — подсвеченным, счет внизу так и не возвращался, а тронутый флаг
оставался подросшим, как названный. Поэтому **каждое** правило `:hover` на
странице — и в `layout.css`, и в блоках — стоит под `@media (hover: hover)`.
Фокуса это не касается: `:focus-visible` нужен всем, и в общем селекторе с
наведением его не оставляют — иначе он уедет под тот же вопрос. Нажатую кнопку андроид подсвечивает серым прямоугольником поверх нее,
айфон не показывает ничего — поэтому подсветку снимаем
(`-webkit-tap-highlight-color`), а отклик пишем общий, `:active` у контрола.
Палец, задержанный на тексте, на обеих системах зовет выделение — лупу и
ручки на айфоне, ручки и «Копировать» на андроиде, — и такт под этим пальцем
уже не играет: читатель хотел перелистнуть, а получил меню. На узком экране
выделения нет (`user-select` и `-webkit-touch-callout` у `body`): страница не
документ, все числа и так на картинке. На широком выделение остается.

**Кегль назначаем мы, а не айфон.** Safari на телефоне умеет раздувать текст
сам: смотрит на ширину коробки, в которой текст стоит, и если она заметно
шире окна — прибавляет кегля. Это помощь страницам, которые про телефон не
знают. Нашей она во вред: коробок шире окна тут две, и обе нарочно —
карточка следующего раздела ждет за правым краем, а у сжатого переходного
экрана коробка расширена ровно на долю сжатия. Прибавка в такой коробке —
это кегль, которого не было, когда каркас мерил строку, то есть ровно то
расхождение, из-за которого заголовок уезжает за край. Отсюда
`text-size-adjust: 100%` у `html`. Проверить это можно только на айфоне:
на маке Safari такого свойства не знает вовсе и выбрасывает его из правила.

**Кроссфейд, в котором можно остановиться, должен быть верным в каждой
точке.** На телефоне анимация привязана к пальцу, и читатель волен замереть
посередине: два варианта заголовка профессий там показывались разом, по
половине высоты каждый. На узком экране такие переходы либо убирают, либо
делают мгновенными.

**Canvas.** Через `mountCanvas(wrap, paint, alt)` — он сам подпишется на
ресайз. Внутри `paint()` учитывать `devicePixelRatio` (ограничивать двойкой) и
масштабировать содержимое под размер контейнера, а не под фиксированный размер.

`alt` — что на картинке, словами. Холст для экранного диктора пустое место:
без подписи блок теряет картинку целиком, с подписью она читается как
изображение. Холст, который только украшает уже сказанное словами (поезд
рядом с легендой), подписи не получает и прячется — это про него честный
ответ, и `mountCanvas` делает так сам.

Если картинка меняется, подпись переписывают там же, где считают числа для
экрана (`canvas.setAttribute('aria-label', …)` в своем `render()`), — и
считают **из состояния, к которому картинка едет, а не из нарисованного
кадра**. Цикл отрисовки запаркован, пока блок за экраном: подпись, снятая с
кадра, поймает анимацию на полпути и такой и останется — «3 электробуса»
вместо 260.

**Следить за размером — через `onResize(el, fn)`** из `lib/ui.js`, не через
`new ResizeObserver` напрямую. Он отвечает на следующем кадре: обработчик,
который померил и тут же написал (выровнял колонки, ужал иконку), меняет
раскладку внутри той же порции уведомлений, и браузер говорит об этом вслух —
«ResizeObserver loop completed with undelivered notifications» летит в консоль
необработанной ошибкой. Страница, которая так кричит по двадцать раз за
чтение, — это страница, чью консоль перестают читать.

**Размеры в канвасе клампить.** `roundRect` и `createRadialGradient` отвечают
на отрицательный радиус исключением, а не кривой картинкой: на низком окне
геометрия ужимается до отрицательной, и блок падал в пустой холст. Радиус и
стороны прижимать к нулю там, где они рисуются.

**Анимации.** Перекраска/появление — 620мс, `1 - (1-p)³`. Ширины и мелкие
переходы — 260мс `ease`. Наведение — 140–160мс.

**Язык.** Интерфейс и тексты — по-русски (буква «ё» не используется, как в
текущих подписях). К читателю обращаемся на «ты»: «попробуй», «наведи»,
«выбери». Комментарии в коде — по-английски, коротко и по делу.

Правила текста проверяет скрипт — он ищет «ё», разделитель «·», обращения на
«вы» и длинные числа мимо `nf()`:

```bash
python3 tools/check-texts.py
```
